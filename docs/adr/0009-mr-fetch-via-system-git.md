# MR objects are fetched with the system git

ADR-0006 resolves an MR's `diff_refs` and then `git fetch`es the missing objects into the local Repository. That fetch shells out to the system `git` instead of libgit2. libgit2 needs an explicit credentials callback, and even with one it ignores `~/.ssh/config`, Pageant, the Windows OpenSSH agent, and credential helpers. The result was `authentication required but no callback set` on any SSH remote whenever an MR needed a real fetch. The system git authenticates exactly as the user's terminal does. There is no libgit2 fallback. If `git` is missing from PATH, the MR fails with an install hint.

**The fetch must stay invisible in the user's repository.** It passes a URL rather than a remote name, so `refs/remotes/*` is untouched. Its refspecs have no destination (`refs/merge-requests/<iid>/head` plus the missing SHAs), so it creates no refs at all. It also passes `--no-write-fetch-head --no-tags --no-recurse-submodules --no-prune --no-auto-gc --no-auto-maintenance -c fetch.writeCommitGraph=false -c gc.auto=0 -c maintenance.auto=false`. The only lasting effect is new objects in the object store. Those objects are unreachable, so a later `gc` may drop them. That is fine because `fetch_oids` fetches only what is missing, and re-opening the MR re-downloads it.

**It never prompts.** It sets `GIT_TERMINAL_PROMPT=0` and `GCM_INTERACTIVE=never`, and sets `GIT_SSH_COMMAND="ssh -o BatchMode=yes"` unless the user already configured `GIT_SSH_COMMAND`, `GIT_SSH`, or `core.sshCommand`. It uses a null stdin and `CREATE_NO_WINDOW` on Windows, and kills git after 60s. On failure, git's stderr is shown verbatim with a hint to run `git fetch` in a terminal, and there is no retry. Lock contention with the user's own git is rare, and clicking the MR again is cheap.

**Why `refs/merge-requests/<iid>/head`:** GitLab always publishes it, including for fork MRs whose commits are not reachable from any branch. Fetching by bare SHA alone depends on server `allow*SHA1InWant` settings.

**Considered options:** a libgit2 credentials callback (the gaps listed above); a private cache repo with alternates, which gives zero writes to the user's repo but brings cache lifecycle and an extra ODB on every open; writing `refs/reviewfox/*` so objects survive gc, which clutters `git log --all` and IDE graphs and needs cleanup. The old `refs/reviewfox/fetch/<sha>` refs from the libgit2 version are left in place.
