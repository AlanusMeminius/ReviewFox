# Exclusive Entry chrome: unified capsule, last-MR memory

Branch Browser and MR selection must not co-appear in chrome: a Workspace selects exactly one Entry at a time. When GitLab chrome applies, titlebar Entry chrome is one unified capsule (ADR visual source: `prototype/entry-kind-switch.html` variant A3)—kind switch and current-value hit targets share one hull. Default selected Entry on launch is Branch Browser. Switching to MR restores a Workspace-persisted last MR Entry label when present; otherwise opens the MR picker. Dismissing the picker with nothing selected leaves an empty MR kind (`Select MR…`); the value hit reopens the picker. The last MR label may remain persisted while the selected Entry is Branch—it is memory for return, not a second selected Entry and does not drive Comparison until MR is selected again.

**Considered options:** dual titlebar pills (status quo); capsule-track segment + separate value pill; peer capsules; morphing pill + kind menu; sidebar Entry sections; session-only last-MR memory; clearing last-MR whenever Branch is selected; forbidding empty MR kind (force back to Branch on dismiss). Rejected: dual pills co-advertise two Entries; track/peer styles fought the capsule language; sidebar moved kind switch off the accepted beads-rail chrome; session-only memory loses return-after-relaunch; clearing on Branch made Branch↔MR toggling heavy; forbidding empty MR kind fought the open-picker-on-enter path.
