# MR comment Publication preserves the reviewed version

Publication extends the local DraftComment lifecycle with an explicit first publish and synchronized subsequent body saves and deletion. The first release supports only full GitLab MR diff versions, including historical versions, and reads only the counterparts ReviewFox created. Branch Browser and Uncommitted Reviews have no remote publication model and will not acquire manual MR binding. This supersedes ADR-0006's prohibition on publishing and the read-only-forge restriction repeated in ADR-0015; their MR discovery, metadata, authentication storage, and resolution decisions otherwise remain.

Keep Comparison identity and the detached Review snapshot (ADR-0002, ADR-0005). Capture the originating MR target and complete reviewed diff version separately, and submit positions for that version. GitLab tracks them into newer versions or preserves them as outdated; ReviewFox does not silently change local Anchors or substitute latest SHAs. Rejecting all historical publication would prevent a normal GitLab workflow, while copying old line numbers into a new version could attach comments to unrelated code.

Persist local comments, their Publication correspondence, and pending operations so reopen, partial failure, and uncertain network outcomes can be recovered. A narrow publishing boundary owns preparation and per-comment outcomes; the GitLab adapter owns GitLab payloads and position translation. Future GitHub and Bitbucket adapters must preserve platform differences instead of inheriting a GitHub-shaped batch review ID. Use the existing asynchronous HTTP client and keychain connection rather than introducing a required `glab` installation.

Uncertain create recovery uses a persisted operation marker hidden in GitLab's rendered comment body and omitted from local editing/Export. Recover correspondence only from a unique remote author/marker match; this is a lookup mechanism, not a server uniqueness guarantee. Ordinary failures require explicit retry, and uncertain creates permit read-only rechecking, website inspection, or explicitly confirmed republishing. This trades a raw-Markdown-visible marker for recoverability without pretending GitLab supplies an atomic idempotent create. Website/local body divergence is shown for explicit resolution; restart and network recovery never automatically send writes.

Cross-section ranges, importing website-authored comments, the full remote discussion UI, and commit-subset publication are outside the first release. They remain tracked options; future GitHub and Bitbucket support is an agreed direction, not part of this implementation. See [product direction](../product-direction.md).

Implementation status: the first-release operation paths are implemented and controlled tests pass. Actual marker rendering, historical/range positions and self-managed server compatibility still require [live acceptance](../gitlab-publication-acceptance.md); the marker-rendering statement above is the intended contract, not a completed server observation.
